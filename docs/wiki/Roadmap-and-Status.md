# Roadmap and status

The roadmap is organized as capability milestones rather than calendar promises.

## M0 — contracts and fixture feed

Portable Candidate, RankedCandidate, Explanation, Interaction, and Policy contracts; deterministic ranking; persistence; and a minimal API establish the reference behavior.

## M1 — useful open-web slice

Open-web sources, a private responsive feed, source/context filtering, self-hosting, and policy import/export make the system useful without a model API.

## M2 — semantic personalization

Local embeddings, novelty/similarity, preference state, saturation controls, exploration, and offline evaluation deepen ranking while preserving inspectability.

## M3 — personal history

Historical imports, optional personal-data bridges, provenance exploration, and bootstrap suggestions turn past activity into explicit evidence rather than invisible platform state.

## M4 — policy control

Visual editing, temporary contexts, natural-language proposals, and before/after simulation make policy changes easier to reason about without surrendering control.

## Later

Additional authenticated adapters, learned/bandit rankers, richer clients, and optional federation are deliberately downstream of the single-user product.

## How to read status

The [roadmap document](https://github.com/pH34r-pH/the-personal-algorithm/blob/main/docs/roadmap.md) states intended milestones. The default branch and its tests state implemented behavior. Issues and pull requests are the live planning surface. Do not infer implementation merely because an item appears here.
